# 需求文档：项目使用指南文档（docs/guide.md）

- 任务：项目使用指南文档
- 作者：PM
- 状态：待规划 / 设计 / 实现

## 1. 背景与目标

### 背景

仓库现有文档分工明确：`docs/architecture.md` 讲架构与安全设计、`docs/format.md` 讲加密保险库文件格式、`docs/task-list.md` 是功能任务清单，`AGENTS.md` 面向贡献者描述仓库规范，`README.md` 只保留极简入口。但对新加入项目的开发者而言，缺少一份「先读我」的使用指南：不知道项目是什么、环境要装什么、如何在最短时间内把项目构建并跑起来、测试怎么跑、目录结构长什么样、深入细节该看哪份文档。新人往往要在 README、AGENTS.md 与 docs/ 之间来回跳转拼凑信息。

### 目标

新增 `docs/guide.md`，作为项目的第一份使用指南：

1. **项目简介**：用一两段话说明项目是什么（跨平台密码管理 App）、覆盖哪些平台、核心功能是什么、当前处于什么阶段。
2. **快速开始**：给出从零开始的环境要求与「构建 / 运行 / 测试」命令，明确每条命令应在哪个目录执行，让新人在 10 分钟内把项目跑起来。
3. **目录结构说明**：解释仓库关键目录与文件的职责，让新人能快速定位代码位置。
4. **文档导航**：链接 `docs/architecture.md`、`docs/format.md`、`docs/task-list.md`，指引按需深入。

目标读者：刚加入项目、尚未熟悉仓库的开发者（含 AI 团队角色，如后端、前端、QA、Review）。

### 成功标准

- 新人仅凭 `docs/guide.md` 即可完成环境准备、构建、运行、测试，无需翻阅其他文档补全命令。
- 指南内容与仓库现状（`AGENTS.md`、`README.md`、`docs/`）一致，不引入新的技术决策或未经实现的功能承诺。
- 指南全文中文、Markdown 格式，符合仓库文档风格。

## 2. 用户故事

- **US-1**：作为刚加入项目的新开发者，我希望先读一份「项目使用指南」，其中包含项目简介与快速开始（构建 / 运行 / 测试命令），以便尽快了解项目是什么并把它跑起来。
- **US-2**：作为需要深入某个领域的开发者（或维护者），我希望指南提供目录结构说明并链接架构、文件格式、任务清单等权威文档，以便按需深入而不必翻遍整个仓库。
- **US-3**：作为 QA / Review 角色，我希望指南内容与仓库现状一致、不包含未经实现的功能承诺，以便它作为新人入口文档长期可信、可维护。

## 3. 验收标准（Given-When-Then）

- **AC-1 文档存在且位于约定路径**
  - Given 仓库的 `docs/` 目录
  - When 查找项目使用指南
  - Then 存在 `docs/guide.md` 文件（Markdown、中文撰写）

- **AC-2 项目简介准确描述项目定位**
  - Given 阅读 `docs/guide.md` 的「项目简介」章节
  - When 与仓库实际情况核对
  - Then 准确说明：基于 Tauri 2 + Rust 核心的跨平台密码管理 App，覆盖桌面端（Windows、macOS、Linux）与移动端（Android、iOS），核心功能为密码记录与安全管理，当前处于早期开发阶段

- **AC-3 快速开始给出环境要求**
  - Given 一个尚未安装依赖的新开发者按指南操作
  - When 阅读「快速开始」章节
  - Then 指南明确列出所需环境（Rust 工具链、Node.js / npm），并在 Linux 桌面端场景下列出 Tauri 所需的系统开发包（如 `pkg-config`、`libwebkit2gtk-4.1-dev`、`libgtk-3-dev` 等）或指向 `AGENTS.md` 对应章节

- **AC-4 快速开始给出构建命令与执行目录**
  - Given 开发者准备构建项目
  - When 按指南执行构建
  - Then 指南给出正确的构建命令（Rust 侧如 `cargo check --workspace` / `cargo build`，在仓库根目录执行；前端侧如 `npm install`、`npm run build`，在 `app/` 目录执行），命令与仓库实际配置一致

- **AC-5 快速开始给出运行命令与执行目录**
  - Given 开发者准备在本地运行应用
  - When 按指南执行运行命令
  - Then 指南给出桌面应用本地运行方法（`app/` 目录下 `npm run tauri dev`）及可选的纯前端开发服务器（`npm run dev`），并说明各自用途

- **AC-6 快速开始给出测试命令与执行目录**
  - Given 开发者准备执行测试
  - When 按指南运行测试
  - Then 指南给出测试命令及执行目录：Rust 测试在仓库根目录（如 `cargo test --workspace`），前端格式化校验在 `app/` 目录（如 `npm run format:check`），与 `AGENTS.md` 一致

- **AC-7 目录结构说明与仓库实际一致**
  - Given 阅读指南的「目录结构」章节
  - When 与仓库实际布局核对
  - Then 说明 `core/`（共享 Rust 核心，不依赖 Tauri）、`app/src-tauri/`（Tauri 后端与平台接入）、`app/ui/`（React 前端）、`assets/`、`docs/` 等关键目录职责，并说明测试归属（Rust 集成测试在 `core/tests/`、前端测试在 `app/` 内）与 `src-tauri/gen/` 不进版本库等事实，无虚构目录

- **AC-8 链接既有文档且目标存在**
  - Given 指南中需要深入阅读的场景
  - When 点击 / 核对指南中的文档链接
  - Then 指南包含指向 `docs/architecture.md`、`docs/format.md`、`docs/task-list.md` 的相对链接，且这三个目标文件在仓库中均存在

- **AC-9 内容与现有文档一致、不引入新承诺**
  - Given 指南全文
  - When 与 `AGENTS.md`、`README.md`、`docs/` 现有文档交叉核对
  - Then 不包含冲突表述（如版本号来源、安全架构、V1 功能范围、命令行为），不承诺未经实现的功能或时间表，不引入新的技术决策

## 4. V1 范围

### V1 包含

- 新增单个文档 `docs/guide.md`，包含以下章节：
  1. 项目简介：定位、平台覆盖、核心功能、当前状态简述
  2. 快速开始：环境要求（含 Linux 系统依赖说明）、构建、运行、测试命令及执行目录
  3. 目录结构说明：关键目录 / 文件职责
  4. 相关文档导航：链接 `architecture.md`、`format.md`、`task-list.md`
- 全文中文、Markdown 格式，风格与现有 `docs/` 文档一致

### 明确非目标（V2 及以后 / 范围外）

- 不修改 `README.md`、`AGENTS.md` 或任何其他现有文档；若后续需要与 README 去重或整合，另立任务处理
- 不新增其他新文档（如 CONTRIBUTING、FAQ、故障排查手册、用户操作手册）
- 不编写应用功能操作手册（界面各功能的逐步使用说明），此类内容属应用内引导 / 用户手册范畴
- 不写实现细节、内部 API 或代码级说明，此类内容留给架构师与开发文档
- 不做技术选型、不引入新工具 / 新依赖（见第 5 节）
- 不承诺 V2 功能（自动填充、云同步、生物识别等）的实现时间表

## 5. 不做技术选型（留给架构师）

以下事项不属于产品需求，由架构师 / 实现角色在 design 阶段决策，本 PRD 不预设立场：

- 指南文档的章节组织方式、目录树如何绘制（文本树 / 图表）、是否使用代码块高亮等呈现形式
- 是否与 README 合并、拆分或在 README 中增加指向本指南的链接
- 命令示例的精确写法与验证流程（如是否需要真实执行验证）
- 不评估构建工具链、不新增任何依赖或 CI 改动
